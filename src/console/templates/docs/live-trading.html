Real orders are possible only when all four conditions hold, checked every cycle:

  1. [EXECUTION] mode = live in config/scanner.ini.
  2. LIVE_TRADING_CONFIRM=I ACCEPT REAL-MONEY RISK in .env (it cannot be stored in the console vault).
  3. Today's arm file, written by python -m src.execution.live_gate --arm after pre-flight checks and a typed ARM <date>. It expires at the end of the day.
  4. Not in mock mode.

What protects a live position

  • Pre-trade validation of data freshness, quote age, contract key and expiry, session time, margin, lot cap (max_live_lots), stop validity, position limits, duplicates, broker connectivity and the daily order count.
  • Entries are LIMIT orders that are cancelled, never chased, if not filled in time. Exits re-price to the bid, then use MARKET with exchange protection.
  • A protective stop order rests at the broker after each fill, so a stop exists even if this computer stops.
  • Every order has an idempotency key and broker tag; a timeout never causes a duplicate.
  • Broker positions are reconciled every reconcile_seconds; a mismatch blocks new live entries.

From the console

You can see whether live trading is armed (status bar and Risk page), watch broker positions and fills (Broker monitor) and disarm immediately. Arming is not available in the browser by design.

Before arming

Paper trade for several weeks, compare lanes, read the backtest report, keep max_live_lots = 1, check the Upstox order endpoints against the current Upstox documentation, and confirm your broker's current requirements for retail algorithmic orders under SEBI's framework.
