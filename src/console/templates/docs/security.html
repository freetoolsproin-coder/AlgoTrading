Accounts

  • Passwords are stored as PBKDF2-SHA256 hashes (600,000 iterations, random salt). 12+ characters with mixed character types are required.
  • Optional two-factor sign-in with any TOTP authenticator app; set require_2fa_for_admin = true to enforce it for admins.
  • After max_login_failures failures an account locks for lockout_minutes; repeated failures from one address are throttled.
  • Sessions are rotated at sign-in, expire after session_minutes of inactivity, and use HttpOnly, SameSite=Strict cookies (Secure with secure_cookies = true).
  • The first admin can only be created in a terminal on this computer.

Requests

  • Every form carries a CSRF token. A strict Content-Security-Policy allows only the console's own scripts and styles; framing is refused.
  • Backtest reports open in a sandboxed origin without access to the console's cookies.
  • CSV exports neutralise spreadsheet formulas.

Credentials

  • The vault encrypts each value with Fernet. Its key is protected with Windows DPAPI (tied to your Windows user) or supplied as CONSOLE_MASTER_KEY.
  • Stored values are never sent back to the browser. Changes are audited.
  • Logs mask anything that looks like a bearer or Telegram token.

Network

The console binds to 127.0.0.1. For remote access use a VPN or an HTTPS reverse proxy (Caddy, nginx, IIS) and set secure_cookies = true. Never expose it over plain HTTP.

Audit log

Sign-ins (and failures), safety actions, credential and user changes, backtest runs and downloads are recorded with user, time and address in a hash-chained, append-only table.
