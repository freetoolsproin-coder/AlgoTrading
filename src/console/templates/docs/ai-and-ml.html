The ML trade filter

The scanner's filter (src/scanner/ml_filter.py) is a logistic regression with readable weights. For every confirmed breakout it estimates the chance that the index reaches 1.5 R before the stop within the holding time. Its inputs are the rule engine's own measurements: score families, RSI, ADX, compression, distance beyond the level, time of day, VIX, level strength and, live, futures and breadth data.

How it is tested

Walk-forward: train on everything before a 30-day window, test on that window, move on. Only those out-of-sample predictions are scored. The model is approved, and may then block entries below its threshold, only if all four checks pass:

  • 150 or more out-of-sample setups;
  • AUC of 0.55 or more (0.50 is a coin flip);
  • Brier skill above 0 (its probabilities beat simply using the base rate);
  • the setups it keeps average at least 0.05 R more than all setups.

Otherwise it is advisory and changes nothing. The rules always decide first; the filter can only remove trades, never add them.

Training from the console

Admins use ML lab → Train and test, which runs python -m src.scanner.ml_filter --train in the background. The scanner reloads the model file by itself. Live setups logged in data/prebreakout.db are included in every retraining.

Reading the ML lab

  • Calibration: when the model says 40%, about 40% should succeed. Bars far from the dots mean its probabilities cannot be taken literally.
  • Strongest features: standardised weights. They show association in past data, not cause.
  • R here is measured on the index, before option pricing and costs, so it is not P&L.

The AI assistant

A chat page that answers questions about your own data with Claude (Anthropic's API). Claude does not see your databases. It chooses among read-only lookups that return the console's own calculations:

  • overview, books, performance, breakdowns (book, month, exit reason, index and side, hour, weekday);
  • individual trades (up to 50 at a time), risk limits and today's usage, system health, ML filter results.

The instructions it runs under require: every number from a lookup, the source named (live, paper, backtest), no adding sources or overlapping books, small samples called out, no buy/sell advice or predictions.

Setting it up

  1. Create an API key in the Anthropic Console.
  2. An admin saves it as ANTHROPIC_API_KEY under Credentials (encrypted).
  3. Optional, in [CONSOLE]: ai_model (default claude-sonnet-5-5), ai_max_tokens, ai_requests_per_hour, or ai_enabled = false to turn it off.

Privacy and cost

Questions and lookup results go to Anthropic's API under your key and are billed to it; credentials never do. Each question, the lookups used and token counts are written to the audit log. Conversations are kept in memory only and cleared with New conversation or a restart.
